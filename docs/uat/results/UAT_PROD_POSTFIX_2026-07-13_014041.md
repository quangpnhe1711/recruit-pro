### A note on the deploy loop (transparency)
The first deploy (`e645f24`) shipped the public fixes correctly **but my validator-filter fix regressed**:
it built a typed `ValidationContext<T>` via reflection and passed it to the non-generic `ValidateAsync`,
which double-wrapped the instance → `"Cannot validate instances of type 'ValidationContext\`1'"` → **500 on
every endpoint with a validator** (create-job, profile, apply, interview, offer). I caught this from the
container logs, corrected it to the canonical `ValidationContext<object>` pattern (`46cc4d0`), redeployed,
and re-verified. Net: caught and fixed within the deploy loop; current prod is healthy.
